SOTAWatch Connect
=================

[特徴]

SOTAWatch Connectは、SOTAwatch3とPOTAのスポットリストにあるSSBやCWなどのモードの
バッジをクリック可能なボタンに変えるブラウザ拡張機能です。
ワンクリックでスポットされた周波数とモードにQSYすることができます。

[前提条件]

このツールを使用するには、システムにPythonとHamlib(rigctld)がセットアップされている
必要があります。

1. Python環境の確認
Python 3がインストールされているか確認してください。

コマンドプロンプトを開いて次のコマンドを実行します: 
python --version

バージョン番号が表示されれば準備完了です。表示されない場合はpython.orgからPythonを
インストールしてください。

2. Hamlibのインストール
リグをコントロールするためにHamlibが必要です。

Hamlibのリリースノートページからお使いのOSに対応した最新バージョンをダウンロードして
インストールしてください。

3. RigIDの確認 (Hamlib)
お使いの各トランシーバー固有のRigIDを確認するには、以下のコマンドを使用します。
rigctl.exeはHamlibのインストールフォルダのbinフォルダにあります。

rigctl -l

例：
 Rig #  Mfg    Model   Version     Status  Macro
  1020  Yaesu  FT-817  20241117.0  Stable  RIG_MODEL_FT817
  1051  Yaesu  FTX-1   20251224.0  Beta    RIG_MODEL_FTX1

FT-817のRigIDは1020です。


[インストール方法]

1. ブラウザ拡張機能
現在はプライベートリリースのため、ChromeやEdgeをデベロッパーモードまたは開発者モードに
設定してからインストールしてください。

chrome://extensions/ にアクセスします。

「デベロッパーモード」または「開発者モード」をオンにします。

「パッケージ化されていない拡張機能を読み込む」または「展開して読み込み」をクリックし、
このパッケージ内のextensionフォルダを選択します。

2. Pythonブリッジ
ブリッジはブラウザとHamlibの間の中継として機能します。
ブリッジを実行するために必要なライブラリをインストールしてください。

pip install flask flask-cors

注意：うまくいかない場合は
python -m pip install flask flask-cors
を試してください。

3. リグの設定 — bridge/rigs.csv
bridge/rigs.sample.csv を bridge/rigs.csv という名前でコピーし、bridge/rigs.csv をテキストエディタ（Excelでも可）で開いてください。

サンプルの内容は記述例です。お使いのリグとCOMポート番号（Windowsのデバイスマネージャーで確認できます）に合わせて書き換えてください。

name,model,com_port,baud,rigctld_port
FT-817ND,1020,COM3,9600,4533
FTX-1,1051,COM7,38400,4534

列の意味：
name          … 拡張機能ポップアップに表示される名前。自由に決めてください。
model         … HamlibのRigID（上記「RigIDの確認」参照）。
com_port      … リグが接続されているCOMポート。デバイスマネージャで確認してください。
baud          … CAT通信のボーレート。
rigctld_port  … このリグのrigctldインスタンス専用のTCPポート番号。
                 リグごとに必ず異なる番号にしてください。

・1台だけ使う場合は、データ行を1行だけ記述してください。
・リグを増やす場合は行を追加してください（それぞれ別のrigctld_portを指定）。
・rigs.csv は配布パッケージに含まれないため、バージョンアップで上書きされません。

[自動起動の設定 (Windows)]

付属のstart_rig_bridge.vbsとstart_rig_bridge.batを使用すると、PC起動時にrigctld
（rigs.csvに記載したリグの台数分）とPythonブリッジ(rig_bridge.py)の両方をバックグラウンド
（黒いコンソール画面なし）で自動開始できます。

セットアップ手順:

リグの設定:
bridge/rigs.csv に制御したいリグをすべて記載してください（上記参照）。

スタートアップへの追加:
Windowsキー + R を押し、shell:startupと入力してOKをクリックし、スタートアップ
フォルダを開きます。
start_rig_bridge.vbsのショートカットを作成し、そのショートカットをスタートアップ
フォルダに移動します。

再起動:
サインアウトして再度サインイン（または再起動）すると、プログラムがバックグラウンドで
自動的に開始されます。

注意: rigctldがシステムの環境変数（PATH）に含まれていない場合は、start_rig_bridge.vbs
をテキストエディタで開き、冒頭付近のRIGCTLD_EXEの行にフルパスを指定してください。パスに
スペースが含まれる場合は、その行のすぐ上のコメントの例のようにダブルクォートで囲んでください。

[アクティブなリグの選択（拡張機能ポップアップ）]

複数のリグを設定した場合、バッジをクリックした際にどのリグへ送るかを拡張機能に
教える必要があります。

1. ブラウザツールバーの「SOTAWatch Connect」アイコンをクリックします。
2. ポップアップが開き、ブリッジから（GET /rigs）リグ一覧を取得して、rigs.csvで
   設定した名前が表示されます。
3. 今操作したいリグを選択してください。選択内容はchrome.storage.localに保存され、
   次回ブラウザを開いたときも保持されます（毎回選び直す必要はありません）。
4. SOTAwatch3/POTAのモードバッジをクリックすれば、バンド・モードが選択中のリグへ送信されます。

ポップアップに「ブリッジに接続できません」と表示される場合は、Pythonブリッジ
(rig_bridge.py)に到達できていません。下記「トラブルシューティング」を参照してください。
バッジをクリックして「リグが選択されていません」というアラートが出た場合は、先に
ポップアップでリグを選択してください。

[ネットワークとセキュリティの設定]

ブリッジポート（オプション）
デフォルト設定で、このPythonブリッジはポート番号5001を使用します（rigs.csv内の各リグの
rigctld_portとは別のポートです）。もしこのポート番号を別のアプリケーションで使用している
場合は、以下のとおり変更してください。
1. rig_bridge.py の中の BRIDGE_PORT = 5001 を空いているポート番号に変更してください。
2. content.js と popup.js の両方の中の const BRIDGE_PORT = 5001 を1で設定したポート
   番号に変更してください。
3. chrome://extensions/ を開いて、SOTAWatch Connectの再読み込みをしてください。

ファイアウォールに関する警告 (Windows)
インストール後の初回のサインイン（または再起動）の際、Windows Defenderファイアウォールから
「パブリックネットワークとプライベートネットワークにこのアプリへのアクセスを許可しますか?」、または
「Pythonの通信を許可しますか？」というポップアップが表示される場合があります（画面コピーを添付）。

重要:
必ず「許可」をクリックしてください。
「キャンセル」や「ブロック」を選択すると、ブラウザ拡張機能がブリッジと通信できずツールが動作しません。

間違えてブロックしてしまった場合：
「コントロールパネル」＞「システムとセキュリティ」＞「Windows Defenderファイアウォール」＞
「Windows Defenderファイアウォールを介したアプリまたは機能を許可」から、python.exeまたはpythonw.exe、
あるいはrigctldを探し、「プライベート」と「パブリック」の両方にチェックが入っていることを確認してください。

他のCAT制御ソフト（WSJT-X等）との共存について
SOTAWatch Connectは、rigs.csvで設定したrigctld_port（例：4533、4534、…）で、リグごとに
専用のrigctldインスタンスを実行します。

COMポートの競合: 
WSJT-XやTurbo HAMLOGなどの他のソフトウェアが同じCOMポートを直接使用してリグを制御している間、
このツールは動作しません。同じCOMポートに同時にアクセスできるアプリケーションは1つだけです。

共存のヒント:
WSJT-Xを本ツールと同時に使用したい場合は、WSJT-Xの設定で「Radio」タブの「Rig」を直接の機種名
ではなく「Hamlib NET rigctl」に変更し、接続先をそのリグのrigctld_port（localhost:ポート番号、
rigs.csvと合わせてください）に設定することで、このツールのrigctldを介して無線機の制御を
共有できます。

リグ切り替え時のWSJT-X側の設定:
WSJT-Xの「Configurations」メニューを使うと、CAT設定（接続先ポートなど）と
オーディオデバイスの設定をリグごとに1つの「構成」としてまとめて保存でき、切り替えが
メニューから選ぶだけの一手間で済みます。なお、複数のリグが同じ汎用USBオーディオチップを
使っている場合、Windowsの再起動のたびにデバイス番号が入れ替わることがあります。各リグの
USBケーブルを毎回同じ物理ポートに挿す、Windowsの「高速スタートアップ」を無効にする、の
2点で安定しやすくなります。

[トラブルシューティング]

拡張機能のポップアップに「ブリッジに接続できません」と表示される場合
ブラウザ自体はポップアップを表示できていますが、rig_bridge.pyがブリッジポートで
待ち受けていない状態です。ブリッジは通常pythonw経由で動作しており、pythonwはエラーを
含めて何も画面に表示しないため、原因を特定する一番早い方法は以下の通りです。
1. コマンドプロンプトを開き、bridgeフォルダへ移動して、pythonwではなくpythonでそのまま
   実行してください（python rig_bridge.py）。起動時のエラーがあればコンソールに表示されます。
2. 正常に起動すると「RIG Bridge starting...」に続けて設定済みリグの一覧が表示されます。
3. ここで問題が見当たらない場合は、実際に動いているツールの場所（タスクマネージャで
   確認できる実行ファイルの場所）と、今編集しているインストール先が一致しているか確認して
   ください。古いコピーがどこかに残っていたり、スタートアップのショートカットが別の
   フォルダを指していたりすると、タスクマネージャ上は同じように見えても、編集した
   rigs.csvが反映されません。
4. 上記でも解決しない場合は、タスクマネージャでpythonw.exeプロセスの有無、
   bridge/rigs.csvがrig_bridge.pyと同じ場所にあるか、上記のファイアウォール設定も
   合わせて確認してください。

[テストツール]

rigctldの疎通テスト用のツールを同梱しました。
SOTAWatch Connectでリグと通信できない場合にこのツールでテストをすることができます。
テストしたいリグのrigctld_portを引数で指定してください。

python rig_test.py 127.0.0.1 4533

（引数を省略した場合は既定値の127.0.0.1:4533がテストされます。）
正常に動作していれば、リグの現在の周波数とモードを読み取って、現在の周波数+100Hzを設定します。
